# 实验二：基于 Npcap 的以太网数据帧捕获——实验要求

## 一、实验背景与目标

本次实验在 Windows 主机上使用 Npcap 捕获网络数据帧，并由自行编写的 C/C++ 程序提取和显示指定的以太网帧字段。重点是理解 Npcap 的基本架构，掌握捕获设备枚举、打开与实时抓包，并能够根据原始字节正确解析数据帧。

本项目延续实验一的开发仓库与工作习惯：**在 WSL 中开发、交叉编译 Windows 程序，在 Windows 中通过 Npcap 驱动捕获数据**。本实验的实现内容必须位于仓库的 `workspace/` 工作目录下，当前开发分支为从 `main` 派生的 `lab2`。

## 二、原始实验要求

1. 了解 Npcap 的架构。
2. 学习 Npcap 的设备列表获取方法、网卡设备打开方法以及数据包捕获方法。
3. 通过 Npcap 编程，实现本机的数据包捕获，显示捕获数据帧的**源 MAC 地址、目的 MAC 地址、类型字段的值、类型字段之后第一个字节的值**。
4. 捕获的数据包不要求硬盘存储，但应在屏幕上以简单、明确的方式展示；上述四项字段必须显式显示。
5. 程序结构清晰，具有较好的可读性。
6. 撰写实验报告。

## 三、功能要求与验收标准

### 1. 捕获设备的枚举与选择

程序应调用 Npcap API 获取捕获设备列表，输出设备编号、可识别的名称或描述，并允许使用者选择需要打开的设备。设备编号仅对应**本次运行所枚举的列表**，不能永久假定某张网卡始终使用同一编号。

**验收：** 能显示本机可用设备，并正确处理非法编号、空列表与设备枚举失败。

### 2. 打开设备并捕获数据包

程序应使用 Npcap API 打开选定设备，在命令行中持续接收捕获的数据帧。建议提供有限捕获数量参数，便于演示、调试及保存终端运行记录。

**验收：** 程序可在真实 Windows 网络流量出现时捕获到数据包；能够区分超时、错误及正常退出；能关闭捕获句柄并释放设备列表。

### 3. 解析指定的帧字段

对链路层类型为 `DLT_EN10MB` 的常规以太网帧，按字节位置读取：

| 字段 | 字节偏移 | 长度 | 预期显示形式 |
| --- | --- | --- | --- |
| 目的 MAC 地址 | 0～5 | 6 字节 | `AA:BB:CC:DD:EE:FF` |
| 源 MAC 地址 | 6～11 | 6 字节 | `AA:BB:CC:DD:EE:FF` |
| 类型/长度字段 | 12～13 | 2 字节 | `0x0800` 等十六进制值 |
| 类型/长度字段之后的第一个字节 | 14 | 1 字节 | `0x45` 等十六进制值 |

解析前必须确认实际捕获长度至少为 **15 字节**，不能因为捕获包不完整而越界读取。类型/长度字段应按照网络字节序合成为 16 位数值。

**验收：** 在同一条输出记录中明确标注上述四个字段；结合已知字节序列做解析测试，并与 Wireshark 的实际抓包结果核对至少一份以太网帧。

### 4. 链路层边界

开始解析前应使用 `pcap_datalink()` 确认设备的数据链路类型。如果不是 `DLT_EN10MB`，应明确提示该设备不适用当前以太网头部解析流程，避免把回环接口或其他链路层数据当作以太网帧。

**验收：** 遇到不支持的链路类型时有可理解的提示，且不会错误输出虚构的 MAC 地址。

### 5. 终端显示与程序组织

输出应具有清晰字段名，能区分不同捕获记录。帧编号、时间戳、捕获长度可以作为辅助字段，但不得掩盖四项必显字段。源码应将设备枚举、捕获控制、帧解析与终端输出合理分离，避免单个源文件承载全部流程。

**验收：** 终端输出易于阅读，重要函数用途清楚，核心解析逻辑可单独验证。

## 五、本实验不要求的功能

- 不要求保存数据包为 `.pcap` 或其他文件；程序默认不落盘保存原始捕获流量。
- 不要求图形界面、多线程、网络聊天、发包或协议栈实现。
- 不要求解析 IPv4/IPv6、TCP、UDP、ARP 的完整内部字段；这里只需按要求显示以太网头部及其后第一个字节。
- 不要求支持所有捕获设备的链路层类型；当前范围是可以返回标准以太网帧格式的接口。
- 不要求使用混杂模式抓取其他设备的流量。

## 六、报告要求与证据

实验报告应覆盖 Npcap 架构、核心 API 调用、程序功能和模块划分、执行流程图、关键代码说明、实际运行结果、问题及结论。建议使用 LaTeX；语言以清晰、准确、体现初学者理解为原则。

建议保留以下**程序执行证据**（用于报告，不属于保存原始抓包数据）：

1. 网卡枚举结果：证明能够发现本机可用捕获设备。
2. 实时捕获终端：明确显示四项必需字段。
3. Wireshark 对照：同一份或可对应的数据帧中四项字段的核对结果；必须注明如何建立对应关系，不能把两条无关数据帧认作同一条。

## 七、完成判定

只有在以下条件全部满足后，才可宣布“实验二的代码实现完成”：

- Windows 程序从 WSL 编译成功，运行时成功加载 Npcap。
- 设备枚举、设备选择、打开网卡、捕获循环均已在真实环境下运行验证。
- 四项必显字段解析准确，针对短帧和非以太网链路层有处理。
- 能明确退出、释放资源，异常情况下给出有效提示。
- 可重复执行的构建及运行说明已写入仓库文档。
- 提供实际运行记录与验收结论，不把尚未完成的报告或截图标为已完成。
